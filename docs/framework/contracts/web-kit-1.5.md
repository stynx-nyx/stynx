# STYNX 1.5 web kit contract (CTG-0006)

**Authority:** DETRAN C-0002 rev. 2 §6.3–6.6 and OD-S15-01. Every UPS-IFM-01…03, UPS-NGERR-01…04, UPS-SHELL-01…04 and UPS-TEST-02…04 is a 1.5.0 MUST. This contract binds the current STYNX package graph; it does not copy DETRAN code. The public symbols below are proposed for implementation and become final only after generated declaration baselines and publication.

## Current binding surfaces

`packages/preferences/src/preferences.controller.ts` already parses a quoted nonnegative integer revision from `If-Match`, returns 428 on absence and 412 on malformed/conflicting revisions, and emits `ETag: "<revision>"`; the package-specific `PreferencesError` remains compatible. `@stynx-nyx/backend` currently has no generic If-Match helper. `@stynx-nyx/angular` already provides `ErrorInterceptor`, `ErrorBannerService` and `provideStynxAngular`; `@stynx-nyx/sdk` provides `createStynxSdkError(status, payload)`. `@stynx-nyx/angular-ui` has a banner but no error banner or shell. The `angular-auth/testing` and `angular-i18n/testing` entrypoints are empty; `@stynx-nyx/testing` exposes a live Testcontainers harness but no small typed transaction fake. `angular/testing` already owns the SSE fake under CTG-0002 and must be preserved.

The authoritative `law/schemas/error-envelope.schema.json` requires `statusCode`, `errorCode`, `message`, and `requestId`; current `StynxErrorFilter` in `@stynx-nyx/core` emits `code`, `message`, `context` for `StynxError` and passes arbitrary `HttpException` bodies through. The IFM exceptions and their HTTP filter must emit the law shape for the new 428/412 responses. They may include `details` and `retryable` only as allowed by the schema. Do not claim the existing global filter conforms; global migration requires a separately reviewed contract and compatibility evidence. The IFM route decorator must install a scoped filter for its own errors, including errors raised by the handler, and use the incoming `X-Request-Id` or a generated nonempty id. If Nest filter ordering makes scoped handling unreliable, repair the global filter with migration tests rather than ship a divergent envelope. The prompt reviewer must check this decision.

## HTTP preconditions (UPS-IFM-01…03)

Publish from `@stynx-nyx/backend`:

- `@RequireIfMatch()` as a **method decorator** composing a precondition interceptor and `@UseFilters(IfMatchExceptionFilter)`. The interceptor parses before the handler and stores the revision on the request; `@IfMatchRevision()` is the parameter decorator that returns that safe nonnegative integer to the handler. Export `parseIfMatchRevision(value: string | undefined): number`. Missing yields 428 `PRECONDITION:REQUIRED:if-match`; malformed, weak, wildcard, duplicate and unsafe integer tags yield 412 `PRECONDITION:FAILED:if-match`. The grammar is exactly one strong quoted base-10 integer (`"0"`, `"1"`, …), matching the existing preferences revision convention; it is not a generic opaque ETag parser.
- `PreconditionFailedError` (`status=412`) for a genuine current-revision mismatch and `PreconditionRequiredError` (`status=428`) for absence. Public constructors accept a safe message/details without leaking entity content. The shared `IfMatchExceptionFilter` writes the law envelope for these two errors, including one thrown by the handler. Routes using the error without `@RequireIfMatch()` must explicitly register the exported filter.
- `@RevisionETag()` as a method decorator/interceptor that reads a returned `{revision: number}` body after a successful handler and sets a strong `ETag: "<revision>"`. Invalid or absent revision is a programmer error, never a silently missing header. No ETag is emitted on failed commands. Return body remains unchanged.

The consumer checks its current revision atomically when mutating; the decorator parses only the supplied precondition. It must not infer tenant, bypass RLS, perform its own database read, or convert a race to success. Test a real Nest route using both decorators for absent/malformed/weak/conflicting tags, success with the **new** revision in the ETag, and exact schema validation of 428/412 including requestId. Prove the scoped filter catches a handler-thrown `PreconditionFailedError`. Preserve preferences behavior and test it; adopting the generic helper there is optional only if equivalent.

## Angular error boundary (UPS-NGERR-01…04)

Publish `classifyStynxError(error, options?)` from `@stynx-nyx/angular`, returning `{ kind, status, code, messageKey }`. It accepts `HttpErrorResponse`, `StynxSdkError`, and unknown transport errors. It uses `createStynxSdkError` for HTTP normalization and recognizes both current `{code}` and law-schema `{errorCode}` payloads during migration. `kind` is a stable discriminant (`authentication`, `authorization`, `not-found`, `conflict`, `precondition`, `validation`, `rate-limit`, `server`, `network`, `unknown`); status 0 is `network`, 412/428 are `precondition`. It never displays an untrusted server message as an i18n key.

`StynxErrorClassificationOptions` supplies a per-app `messageKeysByCodePrefix` map and `fallbackMessageKey`. Longest matching prefix wins, with an exact code match outranking its prefix; a missing code uses a status/kind fallback. Prefix matching is bounded at a code segment boundary, so `AUTH` does not match `AUTHOR`. `StynxAngularModuleOptions.errorBoundary` carries these options plus `exclude: (request: HttpRequest<unknown>, error: HttpErrorResponse) => boolean`. Both `provideStynxAngular` and `StynxAngularModule.forRoot` pass the same options to the existing `ErrorInterceptor`. Exclusion suppresses the banner but preserves the mapped error for the caller; SSE and screen-local 412 are consumer-configured exclusions, not hardcoded global guesses. Other errors show the localized key through `ErrorBannerService` while preserving `code`, `status`, and safe context. `StynxErrorBannerComponent` in `@stynx-nyx/angular-ui` binds to `ErrorBannerService.current`, translates the key via `StynxI18nService`/`StynxTranslatePipe`, exposes dismiss/action controls, and uses `role="alert"` or a suitable live region. It does not duplicate error state.

Inspector tests use status × code × prefix/key tables, body shape migration, unknown/network cases, exact and prefix precedence, SSE/412 exclusions, and TestBed behavior of both provider paths. The UI test proves show/clear/action and translated text without embedding business message catalogs.

## Accessible shell (UPS-SHELL-01…04)

Publish `StynxShellComponent` and `StynxShellThemeService` from `@stynx-nyx/angular-ui`. Inputs are typed `StynxShellNavigationGroup[]` with `labelKey` and items `{labelKey, route, icon?}`, plus `appTitleKey` and `mainId` (default `stynx-main`). The component projects the app's main content, uses Angular Router links and active-state semantics (`aria-current="page"` for the active item), and does not assume a DETRAN route tree. Every visible and accessible label is an i18n key resolved through `StynxI18nService`, including skip-link, navigation, theme toggle, and collapsed-menu controls. Add corresponding STYNX-owned en/pt-BR catalog keys and regenerate catalog consistency artifacts through the supported command, not manual generated edits.

The first focusable element is a skip link targeting the main landmark; the shell has one named navigation landmark and a polite `aria-live` status region for navigation/theme feedback. Keyboard traversal must reach skip link, nav items, and theme control in sensible order and let the skip link focus the main content. The theme service exposes a signal for `light | dark | system`, persists the explicit preference with a configurable storage key, applies it to a documented host attribute, and handles SSR/storage denial without a crash. A stored invalid value falls back to system. Do not persist a tenant-specific theme in a shared key unless the app supplies a tenant-qualified key. Run `pnpm i18n:extract` for catalog key extraction, then `pnpm i18n:check`; fill the translated en/pt-BR values in the source catalogs.

Test with TestBed and a real router; run Playwright + axe over an actual rendered shell, failing on any `serious` or `critical` violation. The scan itself failing is a test failure. Cover keyboard and persistence reload/invalid/denied storage, and both catalog locales.

`@angular/router` becomes an explicit peer and development dependency of
`angular-ui`; the root Engineer owns the manifest and lockfile change.

## Published testing helpers (UPS-TEST-02…04)

- `@stynx-nyx/angular-auth/testing` exports `createStynxSessionStub(initial?)` with a typed `StynxSessionStub` that implements the observable public surface of `StynxSessionService`: readonly `state` and `active` signals, `active$` of **session state** (the current production type), `snapshot`, permission checks, and controlled `setSession`, `setPermissions`, `deactivate`. Keep the actual `StynxSessionState` shape; do not make `active$` a boolean stream. Provide a ready DI provider helper using `StynxSessionService` as token. Existing and newly added auth/consumer tests must use it instead of a one-off local stub.
- `@stynx-nyx/testing` exports `createFakeTransaction(script)` returning an actual `Transaction` value backed by a deterministic fake PG client, plus a query log/control object. The fake is typed at the public boundary (no consumer `asQueryable` or unsafe cast) and is suitable for unit tests of code that calls `Transaction.query`/`execute`; it is not evidence of transaction, RLS, tenant, rollback, or PostgreSQL behavior. Existing applicable STYNX tests must adopt it. Keep real DB integration tests for every database-facing guarantee.
- `@stynx-nyx/angular-i18n/testing` exports `provideStynxI18nTesting(catalogs, defaultLocale?)` supplying `STYNX_I18N_OPTIONS` and `StynxI18nService` for TestBed without `APP_INITIALIZER`/app bootstrap, plus an explicit `initialize()` or equivalent harness method. The helper supports locale switching and missing-key fallback exactly like the production service. Existing applicable Angular tests must use it.

Build published subpaths and compile reference consumer imports from their package names. No test-only deep imports or `export {}` placeholders. TEST-01 SSE fake is already CTG-0002's responsibility and remains intact.
