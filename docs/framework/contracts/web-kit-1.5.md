# STYNX 1.5 web kit contract (CTG-0006)

**Authority:** DETRAN C-0002 rev. 2 §6.3–6.6 and OD-S15-01. Every UPS-IFM-01…03, UPS-NGERR-01…04, UPS-SHELL-01…04 and UPS-TEST-02…04 is a 1.5.0 MUST. This contract binds the current STYNX package graph; it does not copy DETRAN code. The public symbols below are proposed for implementation and become final only after generated declaration baselines and publication.

## Current binding surfaces

`packages/preferences/src/preferences.controller.ts` already parses a quoted nonnegative integer revision from `If-Match`, returns 428 on absence and 412 on malformed/conflicting revisions, and emits `ETag: "<revision>"`; the package-specific `PreferencesError` remains compatible. `@stynx-nyx/backend` currently has no generic If-Match helper. `@stynx-nyx/angular` already provides `ErrorInterceptor`, `ErrorBannerService` and `provideStynxAngular`; `@stynx-nyx/sdk` provides `createStynxSdkError(status, payload)`. `@stynx-nyx/angular-ui` has a banner but no error banner or shell. The `angular-auth/testing` and `angular-i18n/testing` entrypoints are empty; `@stynx-nyx/testing` exposes a live Testcontainers harness but no small typed transaction fake. `angular/testing` already owns the SSE fake under CTG-0002 and must be preserved.

The authoritative `law/schemas/error-envelope.schema.json` requires `statusCode`, `errorCode`, `message`, and `requestId`; current `StynxErrorFilter` in `@stynx-nyx/core` emits `code`, `message`, `context` for `StynxError` and passes arbitrary `HttpException` bodies through. The IFM exceptions and their HTTP filter must emit the law shape for the new 428/412 responses. They may include `details` and the schema-permitted optional `retryable` boolean. CTG-0006 omits `retryable` from these bodies; the error catalog records `retriable:false`. Do not claim the existing global filter conforms. The IFM route decorator installs a scoped filter for its own errors, including errors raised by the handler. If scoped handling proves unreliable, stop and escalate to the Architect; no global filter migration in CTG-0006. The real-route sensor installs `StynxCoreModule` with its global `StynxErrorFilter` and proves scoped precedence.

Resolve the body `requestId` first from CLS/`RequestContext` when reachable without adding a backend-to-core dependency; otherwise use the response `X-Request-Id` already set by core. Core stores its resolved ID in CLS and sets the response header; it does not assign `request.requestId`. If neither core source is available, accept an incoming `X-Request-Id` only after UUIDv7 validation; otherwise generate a UUIDv7 only when no core context exists. The filter sets or preserves the response header to the exact body value. Supplied-valid and absent-header sensors assert `body.requestId === response.headers['x-request-id']` with the global filter installed. Never echo an unvalidated raw request header or mint a second id after core has resolved one.

## HTTP preconditions (UPS-IFM-01…03)

Publish from `@stynx-nyx/backend`:

- `@RequireIfMatch()` as a **method decorator** composing a precondition interceptor and `@UseFilters(IfMatchExceptionFilter)`. The interceptor parses before the handler and stores the revision on the request; `@IfMatchRevision()` is the parameter decorator that returns that safe nonnegative integer to the handler. Export `parseIfMatchRevision(value: string | undefined): number`. Truly absent yields 428 `PRECONDITION:REQUIRED:if-match`; present but empty/whitespace, malformed, weak, wildcard, duplicate (including comma-joined), whitespace outside the quoted tag, and unsafe integer tags yield 412 `PRECONDITION:FAILED:if-match`. The grammar is exactly one strong quoted base-10 integer (`"0"`, `"1"`, …), matching the existing preferences revision convention; it is not a generic opaque ETag parser. Do not trim or split the raw header.
- `PreconditionFailedError` (`status=412`) for a genuine current-revision mismatch and `PreconditionRequiredError` (`status=428`) for absence. Public constructors accept a safe message/details without leaking entity content. The shared `IfMatchExceptionFilter` writes the law envelope for these two errors, including one thrown by the handler. Routes using the error without `@RequireIfMatch()` must explicitly register the exported filter.
- `@RevisionETag()` as a method decorator/interceptor that reads a returned `{revision: number}` body after a successful handler and sets a strong `ETag: "<revision>"`. Invalid or absent revision is a programmer error, never a silently missing header. With a CTG-0005 command boundary, validation and header selection occur before that boundary commits, so an invalid revision cannot turn a committed mutation into a 500 response. Outside such a boundary, the route owner must prove its revision before a nontransactional mutation or avoid this decorator. No ETag is emitted on failed commands. Return body remains unchanged. CTG-0005's idempotent replay header allowlist must retain `ETag`; if that predecessor has not adopted it, stop integration and repair its contract before dispatch.

The consumer checks its current revision atomically when mutating; the decorator parses only the supplied precondition. It must not infer tenant, bypass RLS, perform its own database read, or convert a race to success. Test a real Nest route using both decorators for absent/malformed/weak/conflicting tags, success with the **new** revision in the ETag, and exact schema validation of 428/412 including requestId. Prove the scoped filter catches a handler-thrown `PreconditionFailedError`. Preserve preferences behavior and test it; adopting the generic helper there is optional only if equivalent.

Register the two `PRECONDITION:*:if-match` codes in `docs/framework/contracts/errors.json` as `statusCode` 428/412, `retriable:false`, with their new law-shape runtime bodies. The catalog edit belongs to Engineer A's lock; Architect reviews the declaration and any policy implications before its commit.

## Angular error boundary (UPS-NGERR-01…04)

Publish `classifyStynxError(error, options?)` from `@stynx-nyx/angular`, returning `{ kind, status, code, messageKey }`. It accepts `HttpErrorResponse`, `StynxSdkError`, and unknown transport errors. It uses `createStynxSdkError` for HTTP normalization. Extend `@stynx-nyx/sdk` additively so `StynxErrorPayload` accepts `errorCode`, `details`, and `requestId` as well as legacy `code`/`context`; `errorCode` wins if both codes occur, `details` maps to safe `context` when `context` is absent, and `requestId` remains available in that safe context without changing `StynxSdkError` construction. The mapped error rethrown by the interceptor retains law or legacy code. Both body shapes have explicit sdk and Angular sensors. Never display an untrusted server message as an i18n key.

| HTTP input                                                                     | `kind`           |
| ------------------------------------------------------------------------------ | ---------------- |
| status 0 or explicit transport failure with no HTTP response                   | `network`        |
| 400 or 422                                                                     | `validation`     |
| 401                                                                            | `authentication` |
| 403                                                                            | `authorization`  |
| 404                                                                            | `not-found`      |
| 409                                                                            | `conflict`       |
| 412 or 428                                                                     | `precondition`   |
| 429                                                                            | `rate-limit`     |
| 500–599                                                                        | `server`         |
| 405, 408, 410, all remaining 4xx, other HTTP status and unknown non-HTTP error | `unknown`        |

Apply the `_VALIDATION_ERROR` code suffix only after status mapping yields `unknown`, including an HTTP status in the last row or a non-HTTP `StynxSdkError` without a status; it never overrides a named status row. Thus HTTP 418 with `X_VALIDATION_ERROR` is `validation`, while HTTP 403 with that code remains `authorization`. Unrecognized non-HTTP exceptions are `unknown` unless the transport explicitly reports status 0. `StynxErrorClassificationOptions` supplies a per-app `messageKeysByCodePrefix` map and `fallbackMessageKey`. Keys match case-sensitively. The lookup order is exact code, then longest prefix ending before a `:` or `_` segment separator, then configured `fallbackMessageKey`, then `ui.error.<kind>`. `AUTH` matches `AUTH:EXPIRED` and `AUTH_DENIED`, but not `AUTHOR`. No substring or case-folded match. `@stynx-nyx/angular-ui` owns every default `ui.error.<kind>` key in its source `src/i18n/en.json` and `pt-BR.json`. Its TypeScript source must reference each key as a literal `ui.error.*` string (for example in an exported `STYNX_ERROR_DEFAULT_KEYS` map), so `tools/i18n-extract.mjs` includes all defaults in `keys.json` and `pnpm i18n:check` accepts the catalogs. The classifier emits those exact keys; Angular itself has no catalog. The classification is total for every listed kind.

`StynxAngularModuleOptions.errorBoundary` carries these classification options plus `exclude: (request: HttpRequest<unknown>, error: HttpErrorResponse) => boolean`. Both `provideStynxAngular` and `StynxAngularModule.forRoot` pass equivalent errorBoundary options to the existing `ErrorInterceptor`. Parity is for classification/banner handling only; existing interceptor registration order differs, so 401 refresh behavior is outside the cross-path parity table and must retain its own compatibility tests. Preserve CTG-0002's built-in `STYNX_SSE_REQUEST` bypass before classification and before `exclude`: it emits no banner and rethrows the **raw** `HttpErrorResponse` to the SSE transport. For non-SSE requests, `exclude` suppresses the banner and rethrows the mapped `StynxSdkError`; non-excluded requests show a banner and rethrow the same mapped error. A screen-local 412 may use `exclude`; do not make every 412 a global exclusion. A sensor proves the SSE fake/transport receives the raw error.

`ErrorBannerState` adds optional `messageKey?: string` and `messageParams?: Record<string, string | number>`. Existing `message: string` remains a human-readable fallback and is never used as a key. `ErrorBannerService` may decorate the fallback with `[tenant]` for compatibility but keeps `messageKey` untouched and carries `tenantLabel` in context; the component prefixes translated output once with that label and must not prefix the already decorated fallback twice. With no `errorBoundary` configured, `ErrorInterceptor` and banner text remain byte-for-byte compatible with the current server-message behavior. When configured, the interceptor stores the key, fallback text, `code`, `status`, and safe context. `StynxErrorBannerComponent` in `@stynx-nyx/angular-ui` binds to `ErrorBannerService.current`, translates `messageKey` via `StynxI18nService`/`StynxTranslatePipe` when present and otherwise shows `message`; it exposes dismiss/action controls and uses `role="alert"` or a suitable live region. It does not duplicate error state.

Inspector tests use status × code × prefix/key tables, body shape migration, unknown/network cases, exact and prefix precedence, SSE/412 exclusions, and TestBed behavior of both provider paths. The UI test proves show/clear/action and translated text without embedding business message catalogs.

## Accessible shell (UPS-SHELL-01…04)

Publish `StynxShellComponent` and `StynxShellThemeService` from `@stynx-nyx/angular-ui`. Inputs are typed `StynxShellNavigationGroup[]` with `labelKey` and items `{labelKey, route, icon?}`, plus `appTitleKey` and `mainId` (default `stynx-main`). The component projects the app's main content, uses Angular Router links and active-state semantics (`aria-current="page"` for the active item), and does not assume a DETRAN route tree. Every visible and accessible label is an i18n key resolved through `StynxI18nService`, including skip-link, navigation, theme toggle, and collapsed-menu controls. Name STYNX-owned shell labels `ui.shell.*` in the angular-ui en/pt-BR catalogs and reference each from angular-ui TypeScript/template source so extraction includes them. Regenerate catalog consistency artifacts through the supported command, not manual generated edits.

The first focusable element is a skip link targeting the main landmark; the shell has one named navigation landmark and a polite `aria-live` status region for navigation/theme feedback. Keyboard traversal must reach skip link, nav items, and theme control in sensible order and let the skip link focus the main content. The theme service exposes a preference signal for `light | dark | system`, persists explicit preference under configurable key `stynx.shell.theme` by default, and applies resolved `light` or `dark` to `document.documentElement` attribute `data-stynx-theme`. `system` resolves using `matchMedia('(prefers-color-scheme: dark)')`, reacts to changes, and applies `light` when SSR or matchMedia is unavailable; it never writes `system` as the applied attribute value. Handle storage denial without a crash. A stored invalid value falls back to system. Do not persist a tenant-specific theme in a shared key unless the app supplies a tenant-qualified key. Run `pnpm i18n:extract && pnpm i18n:check` for catalog key extraction and validation; fill the translated en/pt-BR values in the source catalogs.

Test with TestBed and a real router; render the shell on `reference/web/test/e2e/smoke/shell.spec.ts` through a STYNX-only reference route. The existing `smoke/**/*.spec.ts` category is already in the spa-only `testMatch` and the accessibility gate's required categories; do not edit the frozen `reference/web/playwright.config.mjs` or `scripts/verify-frontend-a11y-gate.mjs`. The spec directly calls axe, asserts zero `serious`/`critical` violations, and lets scan errors fail the test; the existing auto probe alone is insufficient. Required gate: `pnpm --filter @stynx-nyx/reference-web test:e2e --project spa-only`, after Docker compose is available and `reference/api` is built, because that project still boots the shared `serve-reference-api-stack.mjs` web server. Cover keyboard and persistence reload/invalid/denied storage, and both catalog locales. The reference app registers angular-ui catalogs by published `@stynx-nyx/angular-ui/catalogs/*.json` imports.

`@angular/router` becomes an explicit peer and development dependency of
`angular-ui`; the root Engineer owns the manifest and lockfile change.

## Published testing helpers (UPS-TEST-02…04)

- `@stynx-nyx/angular-auth/testing` exports `createStynxSessionStub(initial?)` with a typed `StynxSessionStub` conforming to a public-surface `Pick<StynxSessionService, ...>` including every public service method; it does **not** `implements StynxSessionService`, whose private members make that nominally impossible. Include `login`, `loginRedirect`, `completeLogin`, `logout`, `getAccessToken`, `refresh`, `onAuthFailure`, and `switchTenant` as controllable no-ops/spies with recorded calls. Preserve readonly `state`/`active` signals and `active$` of **session state**; keep the actual `StynxSessionState` shape. `setSession`, `setPermissions`, and `deactivate` are test controls. Export the CTG-0003 production permission matcher or delegate directly to it so stub permission checks have exactly the same wildcard behavior. The CTG-0003 matcher/session source must be integrated before this helper is written. Provide a ready DI provider helper using `StynxSessionService` as token.
- `@stynx-nyx/testing` exports `createFakeTransaction(script, {role})` returning an actual `Transaction` backed by a deterministic fake `PoolClient` and Drizzle database, plus query log/control object. Support `Transaction.query` and `Transaction.execute` by accepting the Drizzle `QueryConfig`/`rowMode` calls those methods make. Select/insert/update/delete builder behavior is out of scope for this fake; real DB integration proves those and every transaction/RLS/rollback guarantee. A typed public boundary means no consumer `asQueryable` or unsafe cast; internal casts needed to satisfy PG's broad client interface stay inside the helper. Add `pg`/`@types/pg` to `@stynx-nyx/testing` manifest as needed, owned by root Engineer. Migrate named applicable STYNX unit tests in the plan, but never replace real DB integration tests.
- `@stynx-nyx/angular-i18n/testing` exports `provideStynxI18nTesting(catalogs, defaultLocale?)` supplying `STYNX_I18N_OPTIONS` and `StynxI18nService` for TestBed without `APP_INITIALIZER`/app bootstrap, plus an explicit `initialize()` or equivalent harness method. Omitted `defaultLocale` uses the first catalog key in insertion order and requires at least one catalog. The helper supports locale switching and missing-key fallback exactly like the production service. Existing applicable Angular tests must use it.

Build published subpaths and compile reference consumer imports from their package names. No test-only deep imports or `export {}` placeholders. TEST-01 SSE fake is already CTG-0002's responsibility and remains intact.
