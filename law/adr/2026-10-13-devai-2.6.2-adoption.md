# ADR-DEVAI-ADOPTION-0024 — Prospective DEVAI 2.6.2 adoption

## Scope and publication prerequisite

The Owner's STYNX 1.6.2 audit-tranche mandate includes the supported upstream
repair and exact published dependency adoption needed to collect evidence. This
decision amends only the installed DEVAI identity and its registered runtime
bindings in [ADOPTION-0022](2026-10-12-supported-scorecard-task-collection.md).
DEVAI 2.6.2 must first be published and independently verified. This draft
asserts no registry identity, installed package, successful migration, reading,
scorecard PASS or STYNX release.

The upstream patch admits only the internally reviewed task-cache path used by
an exact task-bound sensor member and verifies existing inventory outputs before
repeated regeneration. It adds no adopter configuration key, command shape,
sensor population or public action. Wrong-kind commands, extra arguments,
foreign candidates and arbitrary state paths continue to refuse. The declared
task-cache capability is local-write and is not the native-only execution-origin
trace or proof-writing authority; it grants no measurement by itself.

## Exact adoption sequence

1. Independently verify the immutable `@aarusso-nyx/devai@2.6.2` registry
   archive, SRI/SHA identities, complete installed file population, source
   commit/tree, signed tag and release. Architect then advances
   `law/policy/devai-package-identity.json` with those **observed** values.
   Engineer pins the root development dependency and frozen lockfile. No source
   checkout, preview archive or rehearsal package substitutes for publication.
2. Preserve `law/policy/devai-adoption.json` policy 1.6.3 unchanged: its four
   task/population bindings, Angular routes, test roots, surfaces, thresholds,
   CI populations and the two N/A declarations already express STYNX intent.
   Inspector rebinds manifest freezes for the Engineer's actual dependency edit.
3. Under the Architect role, use the installed CLI to inspect the read-only
   `init upgrade --target . --as-role architect --format json` plan. Its
   published migration is expected to be
   `MIG-2.6.2-runtime-repair-identity-refresh`, with `authority` and
   `subprocess-effects` segments. Review the actual plan, obligations and
   target digests before invoking the registered `--write` operation. The
   expected compiled targets are `.devai/config/authority-policy.json` and
   `.devai/config/subprocess-effects.json`, plus the upgrade's own identity and
   receipt targets as actually reported. Never edit `.devai/config` by hand.
4. Confirm the write receipt, generated digests and postchecks, a subsequent
   current/no-op read-only upgrade, and unskipped Doctor. Preserve Constitution
   1.0.2 and its pin, the selected host adapter, forbidden-action receipts,
   trusted verifier, task prerequisites and generated-workflow boundaries.
   An unexpected workflow change requires separate review and an exact-commit
   Owner receipt; the prior workflow source `9b82d91f84ae048c15a67ee92241904265f4ad69`
   and receipt `0685e7b7a8aea73c7f49b799d4934250751431e6` are not rewritten
   by this decision.

## Verification and evidence boundary

Inspector verifies the installed package, exact task/cache path admission,
wrong-kind and extra-argument refusals, repeated inventory regeneration,
cross-candidate custody and failed-generation rollback. Run the existing
task-bound prerequisites and record actual readings only against a clean exact
candidate. A successful bind or Doctor result is not an executed measurement.
Auditor independently checks candidate-bound observations, append-only evidence,
the unchanged 1.5.7 observation bytes and proof-chain prefix, and the actual
scorecard verdict. Preserve `readiness_promoting=false` and the two existing
N/A cells. No k6 or mutation test runs, reduced population, weaker threshold or
synthetic CI history is authorized. Normal signed RC, protected integration and
publication controls remain required for STYNX 1.6.2.
