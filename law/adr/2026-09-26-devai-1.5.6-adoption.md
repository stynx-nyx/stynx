# ADR-DEVAI-ADOPTION-0004 — Adopt DEVAI 1.5.6 as a patch of the 1.5 adoption

**Status:** Accepted.
**Authority:** Architect, under the Owner's explicit 2026-09-26 direction to
adopt the latest published `@aarusso-nyx/devai` and keep STYNX on the most
economical CI posture available.
**Amends:** `ADR-DEVAI-ADOPTION-0003` D1 (exact package identity only).

## Context

`@aarusso-nyx/devai@1.5.6` is the registry `latest`. Against 1.5.0 it changes
only the release host, the evidence-verification publish and policy builder,
the mutation-evidence v2 policy and schema, and the trusted local-RC verifier
package pin. Constitution 1.0.1 is byte-identical
(`ff8c4f099a284b1b42f980742b20c849379ba4e3f357905f36a87648ae3fdeae`), and the
adopter policy, release profile 1.4.0, and task descriptor are unchanged.

## Decision

STYNX pins `@aarusso-nyx/devai` exactly at `1.5.6` with this identity:

| Field             | Value                                                                                                   |
| ----------------- | ------------------------------------------------------------------------------------------------------- |
| Registry tarball  | `https://npm.pkg.github.com/download/@aarusso-nyx/devai/1.5.6/6cfa2d77138e41d50b6864eddfc983a35f25de68` |
| Tarball SHA-256   | `a2f4fbca03cac1a893f059eb0cacbc7466aa0dae1a5903ec99e60bdbe8618752`                                      |
| Source commit     | `0fe5689ce0091cdcb5675b576d9c5be2139ee4ef`                                                              |
| Source tree       | `e3abb760f20989d0e06721cdd96065814667259d`                                                              |
| Signed tag object | `3aba4a1066282b77e2c0b4e233033a39dc477f56` (`v1.5.6`)                                                   |

The generated `.devai/config` files are rematerialized only through
`devai init bind --adopter-policy law/policy/devai-adoption.json`. All other
decisions of `ADR-DEVAI-ADOPTION-0003` stand unchanged, including mutation as
external manual hardening.

CI economy keeps every decision of `2026-08-24-ci-economy.md` (Linux-only PR
lane, superseded-run cancellation, no daily schedule, weekly quiescence-guarded
full audit, template-cloned isolated databases) and re-activates the trusted
local RC gate of `2026-08-16-trusted-local-rc-evidence.md` under DEVAI 1.5.6:

- `.github/workflows/devai-local-rc-verify.yml` is the byte-exact workflow DEVAI
  generates (`attestedRcVerificationWorkflow`). It materializes the verifier
  from the DEVAI-designated package `@aarusso-nyx/devai@1.5.4` (provenance
  `1035c8aad52f4b2beb6a6f010106a4d1866c92dadf3fbae1c6e36e1a4d2ceddf`,
  duplicated in the `DEVAI_LEDGER_VERIFIER_PROVENANCE_SHA256` repository
  variable), executes no STYNX product command, and reports `verified-local-rc`.
- The Owner admitted signer `stynx-inspector-workstation-02` on 2026-09-26.
  Its public key is the only entry in `law/policy/devai-local-rc-trust-store.json`;
  the private key stays outside STYNX and GitHub. The retired signer
  `stynx-inspector-workstation-01` is not re-admitted.
- `law/policy/devai-local-rc-toolchain.json` and
  `law/policy/devai-local-rc-environment.json` record the admitted RC
  workstation controls (environment values as SHA-256 digests only; no registry
  credential is admitted). `pnpm devai:rc:prepare` refuses to run unless the
  workstation matches them exactly.
- Evidence is published as the protected annotated tag
  `devai-local-evidence/<git-tree-sha>`; the `stynx-release-tag-immutability`
  ruleset covers that prefix.

`devai check --only ci-economy` passes every binding rule, and the DEVAI doctor
`trusted-local-rc-boundary` check passes.

The Owner also directed that `verified-local-rc` replace the heavy remote PR
jobs (`stynx-tier-gate`, `unit-tests`, `integration-tests`,
`build (ubuntu-latest)`, `reference-web-e2e`) as required checks. That cutover
changes CI enforcement and is applied as a separate Owner-executed step after
the first green `verified-local-rc`. Until then, the remote jobs stay required
and the gate runs additively.

## Consequences

- Package, lockfile, identity policy, SBOM, and the root-manifest byte freeze
  move together; no product runtime, public API, or DDL changes.
- Every candidate that should carry `verified-local-rc` needs one clean local
  RC run by the admitted signer (`pnpm devai:rc:prepare`, then
  `pnpm devai:rc:publish`). The attestation proves signer identity and byte
  integrity. GitHub does not independently reproduce the workstation's
  execution.
- The fixed release group is not versioned by this adoption. It ships with the
  next release unit.
