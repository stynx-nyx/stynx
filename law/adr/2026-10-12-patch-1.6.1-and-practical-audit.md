# ADR-RELEASE-0002 — STYNX 1.6.1 and practical audit recovery

The Owner directly authorized the 1.6.1 plan on 2026-10-12: fix offline-sync gaps
and evidence collection first, then obtain as many green cells as practical;
execute no k6 or mutation tests; keep DETRAN adoption moving in parallel. This
is a new prospective scope, not an extension or edit of the exact 1.6.0 exception.
It supplies no unperformed check, exact-commit receipt or publication success.

## Scope and compatibility

Start from verified published main `60e53ad791a4d031ab137a344fd994fe97bcb514`
(tree `9249c9325558da557f3f13170941efa2d148fdf8`). Preserve all other worktrees and
historical 1.5.7/1.6.0 evidence. Implement
[ADR-MOBILE-OFFLINE-0005](ADR-MOBILE-OFFLINE-0005-acceptance-evidence.md) as additive
contract corrections with forward migrations. Existing calls/default behavior,
request routes/status/envelopes, tests and thresholds remain required. Release
the fixed group as 1.6.1 only if emitted API compatibility and existing behavior
verify those patch assumptions; a demonstrated breaking change requires a fresh
Owner version decision, never a hidden baseline waiver.

Repair admitted measurement production before interpreting missing readings as
product defects. Use the supported published DEVAI interface, policy-projected
inputs, exact command/environment/toolchain/population identity and fresh
candidate-bound append-only evidence. Inspect the new diagnostic population and
select practical repairs for concrete defects; do not manufacture CI samples,
broaden N/A, alter lookback/minimum samples, weaken classifiers to hide real mocks
or rename tests to evade measurement. Preserve historical observation bytes and
proof-chain prefix. `readiness_promoting=false` remains mandatory.

## Exact publication boundary

The machine scope is [release-scope-1.6.1.json](../policy/release-scope-1.6.1.json),
validated by [its closed schema](../schemas/release-scope-1.6.1.schema.json). It
applies only to uniform 1.6.1 and the same exact 44-package roster. Preserve all
fifteen signed RC nodes, exact task admission and transitive closure, including
ordinary cold-unit `test:performance`; it is not HTTP latency evidence. Formatting,
lint, types, ordinary unit/integration/e2e/coverage, generated/API/trace consistency,
DB fresh install/populated upgrade/RLS, security and release preparation remain.

For this exact validated scope, publication demands unique successful exact-head
`verified-local-rc` with independent exact-tree verification in place of the k6
check. All other versions keep their existing rule unless separately authorized.
No k6 or mutation runs are authorized in this campaign. HTTP performance remains
NOT_OBSERVED and mutation NOT_RUN, never PASS. Existing SLOs, native floors,
comparison thresholds and optional mutation population are unchanged.

Keep protected PR integration, strict required checks, normal hooks, action-specific
Owner receipts, Changesets patch staging, exact-main registry preflight,
`publish:true`, protected environment approval and independent verification of all
44 actual artifacts/integrities/tags/releases with RC-tag preservation. A failed,
partial or ambiguous actual publication stops recovery mutation pending new exact
authorization. The consumed one-time merge-method exception grants no new bypass.
This ADR does not authorize an unknown action-specific receipt in advance.

## Parallel adoption and truthful acceptance

The dedicated DETRAN session may adopt independently verified published 1.6.0 and
prepare thin mappings/tests for 1.6.1. Install a 1.6.1 exact pin only after final
publication verification. Preserve DETRAN characterization, blueprints/generated
outputs, restricted-role/two-tenant tests and unrelated PR179. Production-provider
samples and approved OIDs/anchors remain actual required inputs; test PKI never
substitutes for them.

Feature publication may precede rolling-history or complete audit recovery. Report
the actual publication-time scorecard and remaining cells. Full-green audit,
DETRAN acceptance and dependent issue closure remain evidence-dependent follow-up;
a green observation does not replace release gates. No issue closes from package
publication alone when its required consumer proof remains missing.
