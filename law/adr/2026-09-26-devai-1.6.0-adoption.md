# ADR-DEVAI-ADOPTION-0005 — Adopt DEVAI 1.6.0 for RC task-policy parity

**Status:** Accepted.
**Authority:** Architect, under the Owner's explicit 2026-09-26 direction to
adopt `@aarusso-nyx/devai@1.6.0` in a follow-up to the ledger-gate change.
**Amends:** `ADR-DEVAI-ADOPTION-0004` (exact package identity only).

## Context

Under DEVAI 1.5.6 the first trusted local RC run on the ledger-gate candidate
passed all 15 RC tasks, but the signed export failed with
`POLICY_DIGEST_MISMATCH`. The 1.5.x check runner hashed the mutation-stripped
task descriptor into every task key. The package-owned verifier, used by both
the export and `devai-local-rc-verify.yml`, rebuilds the policy from the
committed `test-tasks.json`, which still carries the optional manual
`test:mutation` node kept by `ADR-DEVAI-ADOPTION-0003` D3. The fix, which binds
task keys to the authored descriptor, shipped in `aarusso-nyx/devai#93`, first
released as 1.6.0.

The 1.6.0 changes to commit grammar, change classes, and changeset retirement
govern DEVAI's own repository. The package ships neither
`commit-grammar.json` nor `change-taxonomy.json`, and STYNX uses no removed
check member. The constitution (1.0.1), the trusted local-RC verifier provider
(`@aarusso-nyx/devai@1.5.4`, provenance
`1035c8aad52f4b2beb6a6f010106a4d1866c92dadf3fbae1c6e36e1a4d2ceddf`), and the
generated verifier workflow bytes are unchanged.

## Decision

STYNX pins `@aarusso-nyx/devai` exactly at `1.6.0` with this identity:

| Field             | Value                                                                                                   |
| ----------------- | ------------------------------------------------------------------------------------------------------- |
| Registry tarball  | `https://npm.pkg.github.com/download/@aarusso-nyx/devai/1.6.0/d67263cb9d84b116fa4637acc8dc22c74f3d3a2a` |
| Tarball SHA-256   | `e42831712152e630cf54fcf6dbd204039ae7e1d7fb3ec57e5fe5ff08ea1755d1`                                      |
| Source commit     | `349894356a89e16d92bcb57581e97ca5fc89a2eb`                                                              |
| Source tree       | `436a88f657d2329b9980eb4aa2c265c9d2261e76`                                                              |
| Signed tag object | `d71cf93113ba26b362f673e76debda5b861f06e3` (`v1.6.0`)                                                   |

Generated `.devai/config` files are rematerialized only through
`devai init bind --adopter-policy law/policy/devai-adoption.json`. The optional
1.6.0 capabilities (change-class binding, credential requirements, backlog,
interactive init, and preflight probes) are not adopted by this decision.

## Consequences

- RC task keys now bind the authored `test-tasks.json`. Every cached local RC
  result is invalidated once, and the next `pnpm devai:rc:prepare` runs the full
  closure.
- `ADR-DEVAI-ADOPTION-0004` remains the record for the ledger gate itself; only
  its package identity is superseded.
