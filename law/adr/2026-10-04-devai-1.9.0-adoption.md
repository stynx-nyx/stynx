# ADR-DEVAI-ADOPTION-0010 — Adopt DEVAI 1.9.0 and constitution 1.0.2

**Status:** Accepted.
**Authority:** Architect, under the Owner's explicit 2026-10-04 direction to
fully adopt `@aarusso-nyx/devai@1.9.0` without leaving artifacts from earlier
versions, with Owner decisions D1–D6 recorded below.
**Supersedes:** the package identity in `ADR-DEVAI-ADOPTION-0005`.

## Context

STYNX was pinned at DEVAI 1.6.0, with bound artifacts from older lines still in
the tree:

- the GitHub Actions host adapter was stamped 1.4.5 and bound a
  `devai-main-observation.yml` that had been removed;
- the post-merge host adapter was stamped 1.2.0-rc.3, with absolute paths to a
  retired trial checkout;
- the generated constitution pointer was stamped 1.4.5.

DEVAI 1.7.0–1.9.0 neither add nor remove a CLI command, keep the engine and
dependency floors, and keep the trusted local-RC verifier at
`@aarusso-nyx/devai@1.5.4`. The generated verifier workflow, hook and
host-adapter generators are byte-identical. These releases do change adopter
materialization in ways that require source changes before any rebind:

- **Ownership matrix (1.7.0, DEVAI ADR-CFG-0002).**
  `init bind --adopter-policy` replaces owned `project.json` rows as a whole
  and retires owned rows that the source does not declare. The source path of
  `/ci_economy` is the top-level `ci_economy` member of the adopter policy.
  STYNX declared `ci_economy.attested_rc` only in the materialized
  `project.json`, so a plain rebind would have removed the `verified-local-rc`
  gate configuration.
- **Scorecard N/A (1.7.0).** The runtime degenerate-cell list was removed, and
  the package default now declares F4:T5. An adopter `scorecard_na`
  declaration replaces that default.
- **Constitution 1.0.2 (1.8.0, DEVAI ADR-GOV-0024).** Article 6 now admits
  client extensions by root and path class; the core path table is unchanged.
- **Operational law (1.7.0–1.9.0).**
  - `forbidden-actions.json` gains an append-only maintenance exemption for
    `law/policy/forbidden-action-authorizations.json`.
  - `subprocess-effects.json` gains templates.
  - `thresholds.json` gains a required `soft_gate` block under a closed
    schema.
- **Evidence anchoring (1.9.0, DEVAI ADR-EVI-0002/0005).** Chain
  verification requires a committed anchor baseline. Every proof line must be
  anchored or declared as an Architect historical gap.

## Decision

STYNX pins `@aarusso-nyx/devai` exactly at `1.9.0` with this identity:

| Field             | Value                                                                                                   |
| ----------------- | ------------------------------------------------------------------------------------------------------- |
| Registry tarball  | `https://npm.pkg.github.com/download/@aarusso-nyx/devai/1.9.0/37594fb078f5098b83b3938a3bc70ac5488c3162` |
| Tarball SHA-256   | `b9813b7dc3697e5cfae4d5746ebf067b22563b38e81058d06c63681938b9e374`                                      |
| Source commit     | `75343991140c223240b51cea80c060c516226945`                                                              |
| Source tree       | `90f0f5b64bf594677f96eebf26ae80cf7da1149e`                                                              |
| Signed tag object | `cdc4d7b1ad3c9ade71d6ab7d73dc2a5e74304308` (`v1.9.0`)                                                   |

1. `law/policy/devai-adoption.json` 1.4.0 declares `ci_economy.attested_rc`,
   byte-equal to the configuration materialized under 1.6.0, and the F4:T5
   scorecard N/A cell copied from the package adopter default. The rebind must
   record no `retired_keys`.
2. **D1:** the constitution is rebound to 1.0.2 through
   `devai init bind --constitution`.
3. **D2:** the optional adopter `authority` extension block is not adopted.
   Adopting it requires its own decision.
4. **D3:** both host adapters are rebound at 1.9.0. The GitHub Actions
   observation workflow `.github/workflows/devai-main-observation.yml` is
   re-created by the 1.9.0 generator, byte-identical to the retired file,
   under an Owner `FORBID-CI-WITHOUT-ADR` receipt. The GitHub Actions adapter
   stays the selected host identity: the post-merge adapter is bound first
   and the GitHub Actions adapter last, the reverse of the package
   install guide. The post-merge binding is specific to one checkout, so as
   the selected identity it fails doctor in every other checkout, including
   the observation workflow itself (`aarusso-nyx/devai#266`). The post-merge
   adapter binds the primary checkout.
5. **D4:** the anchor baseline is written first. The three R-0001 pilot
   proof lines, which DEVAI 1.1.2 wrote before anchoring existed, are then
   declared an Architect historical gap through
   `devai evidence record --kind historical-gap`. The R-0002 lines were
   already anchored. No existing proof byte or chain entry changes.
6. **D5:** the adoption contract test and the task descriptor drop their 1.5
   naming. Renaming the descriptor invalidates the RC cache, which the version
   change invalidates anyway.
7. **D6:** `CLAUDE.md` becomes the single line `@AGENTS.md`, and its
   STYNX-specific guidance moves into `AGENTS.md`.

The `.devai/config` files are rematerialized only by the 1.9.0 CLI, in the
canonical order: constitution, operational law, subprocess effects, adopter
policy, authority policy, then host adapters. The adopter-policy bind runs
after the operational-law bind, which would otherwise overwrite its
projections.

## Consequences

- Every cached local RC result is invalidated once. The next
  `pnpm devai:rc:prepare` runs the full closure.
- Under 1.9.0, commits that only append Owner receipts no longer need a
  receipt of their own. `test/scripts/validate.js` pins that exemption and
  its boundary: a receipt append mixed with another governed path is still a
  finding.
- The new 1.9.0 rule `docs-ia.workflow-page-set` ignores the STYNX
  `dev/operations -> meta/ops` IA override. The workflow reference pages live
  in `docs/meta/ops/workflows/`. Doctor reports the rule as an advisory
  finding until `aarusso-nyx/devai#265` is fixed, and still exits 0.
- `devai init apply harness --include ci --force` is not part of the STYNX
  upgrade sequence. It would overwrite `.gitignore` and the `domains.json`
  client projection, and its CI workflow output is unchanged at 1.9.0.
- `ADR-DEVAI-ADOPTION-0004` and `ADR-DEVAI-ADOPTION-0006` remain the records
  for the ledger gate and the `verified-local-rc` cutover. Only the package
  identity of `ADR-DEVAI-ADOPTION-0005` is superseded.
- `law/policy/retired-governance-catalog.json` 1.1.0 lists the retired paths
  that later ADRs re-created. Their retirement digests remain historical
  record.
- An adopter upgrade command that would replace this manual sequence is
  requested upstream in `aarusso-nyx/devai#264`.
