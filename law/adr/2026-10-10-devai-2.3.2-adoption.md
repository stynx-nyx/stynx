# ADR-DEVAI-ADOPTION-0017 — Adopt DEVAI 2.3.2

**Status:** Accepted.
**Authority:** The Owner's 2026-10-10 authorization for separate Architect
and Inspector sessions to finish DEVAI 2.3.2 adoption and rebuild the 1.5.6
lane. The Owner explicitly retained the 1.5.6 / 1.5.7 split. Certification
and publication remain held.
**Supersedes:** the package identity of `ADR-DEVAI-ADOPTION-0013`.

## Context

The 1.5.6 draft was prepared from `origin/main` commit
`f3edd68f7c5c78c9e614b3b70629b5ec76959049` under DEVAI 2.3.0. Upstream
issues #381, #382, #383 and #389 exposed observation workflow pin drift,
undeclared subprocess shapes, a dangling predecessor observation, and
observation installs running repository lifecycle hooks. The published 2.3.2
package contains the repairs. The existing observations remain historical
evidence; their removal is neither necessary nor authorized by this adoption.

The installed package's read-only `init upgrade` plan reported `ready`, no
retired keys, no replaced defaults, no obligations and no refusals. Its
three migrations are:

- `MIG-2.3.1-observation-workflow-pins`: align generated observation action
  pins with the toolchain and serialize duplicate observations per commit
  without cancelling a running observation.
- `MIG-2.3.1-subprocess-effects-pnpm-shapes`: declare the recursive pnpm
  typecheck and performance commands and the corresponding npx shapes.
- `MIG-2.3.2-observation-install-ignore-scripts`: disable workspace lifecycle
  scripts during the generated observation workflow's frozen install.

## Decision

1. Pin the root development dependency `@aarusso-nyx/devai` exactly to
   `2.3.2`. Its identity is recorded in
   `law/policy/devai-package-identity.json` policy version 1.4.0:

   | Field             | Value                                                                                                   |
   | ----------------- | ------------------------------------------------------------------------------------------------------- |
   | Registry tarball  | `https://npm.pkg.github.com/download/@aarusso-nyx/devai/2.3.2/57d145a81f2eae2af30c2e78626ab1f6426c8be8` |
   | Tarball SHA-256   | `df04bfae94257ecc406ca9da0d8b4a83fd1016885bd93144f4b82e9684ec4645`                                      |
   | Source commit     | `915db68119461af83e03e28febf28a139a5a5de9`                                                              |
   | Source tree       | `8e0954e7908219fd345681dde18a2566472c4a61`                                                              |
   | Signed tag object | `e2eeff23933658d711f1195a9c6804c43a666128` (`v2.3.2`)                                                   |

   The downloaded registry tarball matches its SHA-512 integrity; the signed
   tag verifies against the existing protected allowed-signers trust.

2. Materialize only through
   `devai init upgrade --target . --as-role architect --write`. The committed
   upgrade receipt records the three migrations and all generated file
   digests. The package reports all postchecks passed and a subsequent
   read-only plan reports `no-op` with a current receipt. Constitution 1.0.2
   and the trusted local-RC verifier 1.9.0 remain bound.
3. Commit the generated `devai-main-observation.yml` together with its host
   adapter receipt and reference page. An Owner `FORBID-CI-WITHOUT-ADR`
   receipt for that exact commit is required before push under `AGENTS.md`.
   The registered Architect `init upgrade` action supplies the configuration
   binding authority; the current forbidden-actions check reports no
   additional `FORBID-MUTATE-INVARIANTS` receipt requirement for that binding.
   This ADR does not fabricate the CI receipt or authorize publication.
4. Preserve every tracked `.devai/state` observation and all proof history.
   Do not carry the old lane's retirement commit or edit machine state. A
   later observation may supersede a reading through registered verbs.
5. Complete the adoption before rebuilding the 1.5.6 version marker under
   `ADR-DEVAI-ADOPTION-0016`. DEVAI is root-only tooling, so it adds no
   changeset to the four existing feature changesets and changes no emitted
   public declarations. The migration-bearing slice remains 1.5.7.

## Consequences

The package and binding changes invalidate cached candidate evidence. The
old lane's marker and any RC results do not establish readiness for this
rebuilt tree. Role-separated frozen-manifest tests and trace bindings must
be updated, and the exact candidate must pass the ordinary release gates
when those actions are authorized. No RC, certification, push, merge or
publication authority is supplied by this decision.

One sensor-input reference gap remains: the existing `type_check.argv` is
`["pnpm", "typecheck"]`, which the 2.3.2 broker explicitly refuses; the
new admitted workspace shape is exactly `["pnpm", "-r", "typecheck"]`.
The installed `init bind` exposes no sensor-input binding and its closed
adopter-policy schema admits no sensor-input source. ADR-0014's historical
direct-authoring instruction conflicts with the current prohibition on
hand-editing `.devai/config`. This adoption leaves the declaration intact
pending a registered producer or an explicit authority resolution. No new
sensor sweep was run, and no repaired measurement or improved scorecard is
claimed. Ordinary repository typecheck remains a separate gate.
