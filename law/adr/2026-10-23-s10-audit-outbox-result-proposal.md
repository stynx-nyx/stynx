## Accepted bounded decision

The Owner approved exactly these supplemental result corrections and their necessary type/documentation/generator propagation, preserving existing SQL, runtime values, mapper behavior, errors, cursor forwarding and write/request input domains:

1. Audit direct read timestamps become `string | number`, with successful numeric database results limited to ±Infinity. The legacy `/_audit/log` HTTP projection becomes `string | null` through explicit source wire declarations and the reviewed official emitter/SDK design below. Preserve Date→ISO, InvalidDate RangeError, bigint Number conversions, and unchecked cursor JSON null forwarding. Angular `/audit/events` contracts remain separate.
2. Direct retirement receipt returns use a new raw timestamp result shape. The existing named `OutboxEventRetirement` and nested delivery receipt retain their mapped Date guarantee. No retirement input, operation, lease/conflict rule or receipt immutability change.
3. Append event **results** admit `metadata: null`, preserving optional named-object construction. Append/enqueue **inputs** remain unchanged; preserve own-null results and dedup semantics.

No backend stream port/input broadening, SQL exception, normalization, new rejection of a legitimate row, release version, publication, formal DEVAI acceptance or DETRAN/PORM acceptance is requested. Ordinary behavior-preserving caller migrations are included in their corrected result target; they do not each require a separate decision. If implementation requires a different public input/port domain or runtime behavior, return with that concrete difference before proceeding.

## Exact proposed behavior and types

Both current audit mappers implement `value instanceof Date ? value.toISOString() : value`. Therefore successful in-process audit result values are ISO strings for ordinary Date, unchanged custom strings, and unchanged numeric ±Infinity for PostgreSQL sentinel rows. Propose `occurredAt: string | number`, with the numeric database-result branch bounded to exactly ±Infinity. The TypeScript number branch cannot encode those literal sentinels. Date is not a successful returned representation here; Invalid Date still throws the existing `RangeError` at `.toISOString()`. Do not replace this with the raw Date union, coerce infinity to strings/null, reject it early, change timezone/milliseconds, or move the existing failure to row validation.

Keep `AuditLogCursor.occurredAt: string` as the existing declared request payload contract, `AuditLogQuery.cursor?: string` as the encoded request, and `AuditLogPage.nextCursor?: string` as the encoded response. Use a separate internal encoder input shape with `occurredAt: string | number`; do not pretend the produced payload always satisfies the request shape.

**Important correction to the initial Engineer census:** current `decodeCursor` is unchecked `JSON.parse(...) as AuditLogCursor`, not a runtime string/id validator. A tail timestamp Infinity becomes JSON null in the encoded cursor; decoding passes that null onward into the subsequent SQL parameters. Preserve this exact existing runtime limitation and SQL behavior pending focused evidence. Keeping the public request declaration string-only does not authorize adding a strict rejection, manufacturing a resumable cursor, or normalizing null. Replacing the unsafe cast needs an honest internal unknown/JSON shape and validation limited to what the existing path actually establishes; any new rejection of previously accepted payloads is outside this representation-only proposal and must be reported concretely before implementation.

Existing bigint conversions are explicit and stay unchanged: public audit `id` and cursor id use `Number(row.id)`; totals use `Number(rows[0]?.total ?? 0)`. Preserve their current precision/error behavior. No safe-integer cap, decimal-string output, SQL cast rewrite or new validation ceiling is authorized. `findAuditRows` already admits string|number IDs; chain-verification text formatting stays unchanged.

For `/_audit/log`, ordinary JSON serialization turns ±Infinity into null. Propose a distinct wire result `occurredAt: string | null` while preserving the service's in-process string|number result and actual response bytes. A union that merely emits string|number in OpenAPI would still misdescribe sentinel HTTP output. The implementation must use the existing official OpenAPI/SDK generation path with an honest JSON wire projection; do not hand-edit generated trees, add runtime conversion, or hide the discrepancy with an unchecked annotation. Verify existing emitter support and concrete type-only representation before final scope acceptance. Generated declarations and source metadata change; runtime output does not. Audit ID precision remains as today.

## Completed source-only emitter and port design review

### HTTP emitter: explicit wire contract, no false TypeScript return annotation

The actual route emitter is `packages/cli/engines/api-coverage.mjs`, not the core build copier. `discoverNestOperations` takes a controller's explicit return type or follows the service call through `responseTypeName` / `buildReturnTypeIndex`. `operationResponses` then resolves that type through `responseBodySchema`. The schema registry reads TypeScript declarations syntactically; `number` becomes JSON Schema number, and `string | null` becomes `anyOf: [{type:'string'}, {type:'null',const:null}]`. It does not currently model numeric infinity serialization. The core `emit-openapi.mjs` merely copies `docs/framework/api/openapi.json` into dist.

Consequently, annotating the controller as `Promise<AuditLogWirePage>` while returning a service page containing numbers would be a false direct-call guarantee and is rejected. A global number→nullable schema rewrite would also be wrong for unrelated endpoints. Renaming a return type cannot solve the runtime/direct-versus-wire distinction.

Recommended bounded emitter pattern for this one reviewed route:

1. Keep `AuditSqlListItem` and direct `AuditLogItem` result fields `string | number` under the proposed audit correction. Add explicit `AuditLogWireItem` / `AuditLogWirePage` declarations describing the legacy HTTP result. Define the wire item explicitly with the same required/optional fields and `occurredAt: string | null`; this avoids caching the direct result type into the generated SDK component population. The existing emitter supports the required fields, arrays and nullable unions. The wire page preserves `items` and optional encoded-string `nextCursor`.
2. Add a source-only controller method annotation such as `@stynx-json-response-type AuditLogWirePage`. This is a **proposed small extension**, not an existing feature. Parse it from the actual method AST; keep the direct/inferred `responseType` as `Promise<AuditLogPage>` and carry a distinct `jsonResponseType` into response schema resolution. Generated `x-stynx-source-type` remains the honest direct source type; a separate `x-stynx-json-response-type` records the reviewed wire declaration. No annotation changes a function signature or runtime response.
3. Admit only a resolvable named non-generic declaration under the normal source roots; reject duplicate/empty/unresolved/generic/UnknownJson annotations and request-body misuse. No arbitrary JSON schema payload, generic allowlist, cast, suppression or skipped route check. Add Inspector positive/negative cases binding the annotation to this route and its actual serialized sentinel behavior. Ordinary endpoints keep the existing discovery/projection behavior.
4. `GET /_audit/log` → `responses['200'].content['application/json'].schema` references the wire page. Its item `properties.occurredAt` accepts string or null, remains required, and has no new date-time restriction because configured strings were already passed through. The generated example remains an ordinary string. The direct audit package's `AuditLogPage` does not claim a null result.
5. Preserve generated SDK public names with truthful aliases in the handwritten SDK public barrel, as specified in the naming follow-through below. The inspected generator derives model names from component keys and has no existing alias option. Do not drop public imports accidentally, retain a string-only legacy alias, or hand-edit generated trees. This is propagation of the proposed wire correction, not unrelated SDK redesign.

`pnpm api:docs:write` is the official route generator. It writes `docs/framework/contracts/openapi.json`, the legacy `docs/framework/api/openapi.json`, and the offline-e6/offline-ctg9 composition documents. SDK regeneration must use the repository's official SDK generator for the default and generated offline-ctg9 trees. Their checked-in source models/schemas/barrels and generated service response references are in the blast radius; no manual artifact patch. Focused engine tests, actual legacy HTTP serialization, generated consumer fixtures and final public baselines are required. None ran during this source review.

Named object construction versus service guarantee is deliberate: existing callers can continue constructing audit items with strings; TypeScript's numeric branch also admits finite numbers because it cannot express Infinity literals. That does not promise the checked service returns arbitrary finite numbers. Its result validator proves string-or-±Infinity and its existing Date mapper supplies strings. The wire declaration applies to that checked route result, not every independently constructed object with the same broad TypeScript field type. No new validation or narrowing is applied to public write envelopes.

### Cursor preservation without the current unsafe cast

Do not annotate arbitrary JSON as `AuditLogCursor` or add an object/string schema rejection to justify it. Keep the public request payload declaration and existing `JSON.parse` syntax errors. Internally the decoder can return `unknown`, and extraction can follow the exact executed JavaScript operations: falsy parsed values skip cursor handling as today; truthy values access `occurredAt` and `id` without shape checks. A locally typed `unknown`-value property reader may use real type narrowing/property existence while returning undefined for absent properties, preserve primitive boxing behavior, and preserve errors for null/undefined if used outside the existing truthiness guard. It must not introduce new accepted request claims or fabricate a typed row. The resulting unknown values are forwarded as the existing SQL bind values, including null from the generated infinity cursor. Parameter schemas must not add a stricter cursor domain accidentally; enumerate operation-specific legacy behavior in Inspector tests before conversion. No new generic SQL escape is required.

`AuditLogCursor` itself remains the documented string request shape. A distinct internal encoder payload describes the observed string-or-number tail. JSON.stringify and base64url encoding stay unchanged. The accepted-construction domain of the request type and the absence of runtime shape validation are different facts and both must be documented.

### Outbox/backend relationship: exact choices and scope

Within ADR0032's existing pending result correction are: separating `OutboxStreamRow.createdAt` from `OutboxStreamCursor.createdAt`; separating `OutboxEventListPage.nextCursor` from the Date-only query cursor; propagating honest returned types to consumers; requiring narrowing where consumers need a Date; retaining `now(): Promise<Date>` and every input declaration. These are foreseeable type migrations of the enumerated raw result population, not independent permissions per call site. Internal caller updates are authorized once that target correction is approved **if they preserve current runtime values, branch ordering and errors**.

Affected structural API nodes are precisely:

- `packages/outbox/src/event-stream-source.ts`: exported cursor/row and `findById`/`listSince` returns; Date input cursor and `now` remain.
- `packages/backend/src/event-stream/types.ts`: Date-only `EventStreamCursor`, `EventStreamRow`, generic `EventStreamSource<TRow>`, and `StynxEventStreamOptions<TRow>`.
- `packages/backend/src/event-stream/event-stream.service.ts`: `open` generic bound, preflight `getTime` call, mutable cursor and three tick cursor assignments followed by `source.listSince`.
- Backend CTG9 integration obtains the outbox constructor through an existing structural assertion and invokes this seam; source-only production census has no reference-app construction, but that test and published adapter purpose prove the relationship is real. Outbox integration/unit tests and backend export/emitted consumer fixtures also require review. Reference SSE uses its own Date-typed stream source, which should retain its existing contract.

**Minimal result-only option:** leave the backend's existing Date-only port unchanged and expose the now-honest raw outbox result API. Existing Date-only source implementations and reference SSE remain compatible; direct outbox→backend assignment becomes a disclosed compile-time migration issue. Do not make the integration falsely green with its current assertion. Where callers have an independent finite-Date guarantee, a checked adapter can prove it; that guarantee must come from the caller's actual source contract. An adapter rejecting sentinel rows at find/list time would alter this outbox integration's existing behavior and is not a generic fix.

The coordinator selected the result-only disposition: disclose loss of automatic Date-only backend structural compatibility in migration notes, preserve all existing backend ports and input domains, and do not pursue a new raw backend port. Escalate only if implementation establishes that a required internal caller cannot migrate honestly within the intended result correction. Ordinary behavior-preserving caller narrowing needs no separate per-caller approval.

SDK naming follow-through (source reviewed): `packages-web/sdk/codegen/parse.mjs` derives generated model names directly from component keys; `render.mjs` emits matching model/schema files and barrels. No model-alias option was found in that path. `packages-web/sdk/src/index.ts` is a handwritten public barrel that re-exports generated surfaces. Therefore preserve published import names with explicit handwritten re-exports, e.g. `AuditLogWireItem as AuditLogItem` and `AuditLogWirePage as AuditLogPage`, plus corresponding `$AuditLogWireItem as $AuditLogItem` schema-value aliases if those old exports disappear. These are truthful wire aliases, not unchecked result conversions. Source service classes keep their generated existing names; their method returns the wire page, which is equivalent to the compatibility alias. Do not edit generated files to add aliases.

For this minimal path, define the small wire item/page explicitly (same required/optional fields, only timestamp representation differs), and seed response schema generation from `jsonResponseType ?? responseType`. Avoid resolving a wire `Omit<AuditLogItem,...>` into the global shared registry: current object-shape resolution caches the direct result's component and could accidentally retain a second misleading generated string|number AuditLogItem export. Inspector should compare the full generated export set, preserve existing aliases, and verify no direct-result model leaks into the route's SDK. This small explicit wire DTO avoids a broader registry rewrite. The normal SDK generation command is `pnpm --filter @stynx-nyx/sdk codegen`; composition generation uses the same shipped codegen with its composition input/output. No generator was executed.

### Supplemental decision 1: direct retirement receipts, without weakening nested Date guarantees

Pending ADR0032 currently states that `OutboxEventRetirement.retiredAt` stays Date because it reviewed the nested JSON mapper. The direct-return evidence disproves that universal statement. Do not edit the pending question or treat an eventual answer as approving these direct paths.

Recommend retaining the existing `OutboxEventRetirement` named Date shape for legitimate existing construction and mapped nested results, and adding a distinct direct result type (for example `OutboxEventRetirementResult = Omit<OutboxEventRetirement, 'retiredAt'> & { retiredAt: RawTimestampResult }`). Change only the three direct return guarantees/method declarations to that result shape. It includes existing Date construction, custom strings, numeric ±Infinity and InvalidDate preservation with non-null timestamp. `OutboxEventDeliveryState.retirement` remains the original Date type. No changes to `OutboxEventRetirementInput`, actor lookup, lock/lease checks, status guards, idempotency comparison, event-id normalization, immutable receipt/RLS behavior, SQL clock/defaults or conflict errors. Callers assigning a direct result to the old Date shape must narrow; no conversion is inserted for them.

Required observations: ordinary/new receipt, existing receipt replay, direct get, configured parser strings, stock ±Infinity/out-of-JS-range receipts where valid fixture construction permits; compare the nested JSON projection of the same receipt and retain its Date/InvalidDate mapping. Existing integration expects Date for the ordinary new receipt; retain that assertion. Do not mutate production or immutable history to fabricate test evidence.

### Supplemental decision 2: nullable append-result metadata, preserving input domain

`OutboxAppendEvent.metadata?: Record<string,unknown>` is a write input. `OutboxEventRow extends OutboxAppendEvent` incorrectly inherits that non-null shape. `appendManyInTransaction` binds null when metadata is omitted; `outbox.events.metadata` is nullable and both RETURNING and replay SELECT include it unchanged. This is a legitimate successful call, not hypothetical malformed database data.

Recommend `OutboxEventRow` derive from `Omit<OutboxAppendEvent,'metadata'>` and declare `metadata?: Record<string,unknown> | null`, while preserving its other identity/result fields and pending timestamp decision. Keep optional construction compatibility for existing callers; document that actual insert/replay projections return an own metadata key, possibly null. If a stronger required-key method result is useful later, it needs an explicit separate named guarantee rather than making the existing public construction type required. Do not widen `OutboxAppendEvent` / `OutboxEnvelope` inputs to accept null, synthesize `{}`, drop the returned null property, or alter dedup's `IS NOT DISTINCT FROM` comparison. A returned event no longer automatically satisfies an append input when metadata is null; expose that honest migration consequence.

Inspector should observe omitted metadata → own null on insert and replay, object metadata preserved, existing named object construction with omitted metadata, unchanged dedup/conflict behavior, and exact unchanged write input declarations. Other metadata-bearing result interfaces already explicitly allow null and require no additional public widening.

### Scope and blast-radius conclusion

Exactly two additional outbox result deltas were found beyond the pending ADR0032 timestamp/cursor population: direct retirement receipt guarantees and append-result metadata nullability. The complete selected-field census found no further missing optional correlation/destination/idempotency fields: destination is configuration/filter selection, not stored/projected result data; idempotencyKey is required in each event/receipt result and remains optional only in the pre-existing legacy enqueue input. All selected nullable strings, bytes, JSON objects and status/count forms are accounted for above.

Public result definitions/method signatures, their mapped nested counterparts, package export declarations, focused tests and official API baselines are affected. No production reference or browser caller of the direct retirement/event-row result names was found in the source search; that does not erase external public consumers. HTTP dispatcher callbacks receiving OutboxRow inherit the existing pending legacy timestamp correction, but the built-in dispatcher serializes payload only; do not modify its payload/network behavior. Backend stream compatibility remains the coordinator's result-only migration disclosure, with no new backend port/input proposal.

Consolidate these two outbox deltas with the audit direct/wire result correction in one supplemental review, keep ADR0032/0033 questions intact, and implement only the accepted three corrections, retaining the exact adapter/HTTP observations above and disclosing the 25 unresolved audit failures and absent PostgreSQL/emitted-consumer proof. This is not a blanket result-type amendment, full accepted implementation, release classification, publication or downstream acceptance.
