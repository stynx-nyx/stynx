# ADR-RELEASE-0001 — Bounded 1.6.0 publication

## Owner amendment and exact scope

The Owner prospectively reprioritized STYNX **1.6.0 publication before midnight
America/Sao_Paulo on 2026-10-11**. Execute no k6 and no mutation campaign. Stop
pursuing a fully green scorecard as a precondition of this publication. This
amends ADR-0019, ADR-PERF-0001, ADR-PERF-0002 and the 2.6.0 adoption decision only
where their full HTTP performance, upstream long-duration/native/resume or
consumer-completion requirements would delay this exact publication. Historical
decisions, observations and rejected evidence remain preserved.

The machine source is [release-scope-1.6.0.json](../policy/release-scope-1.6.0.json),
validated by its [closed schema](../schemas/release-scope-1.6.0.schema.json).
It applies only to uniform **1.6.0**, the exact 44-package roster and the declared
unchanged RC closure. It grants no exception to a later patch/minor/major release.
The deadline is the Owner's delivery priority, not a success assertion or authority
to bypass a failing retained gate. A missed deadline must be reported honestly.

## Required publication minimum

Use already published and verified DEVAI **2.6.0**. Unpublished diagnostic,
Git-probe, native, durable execution and restart work is deferred from this
critical path; preserve its isolated worktrees and evidence without adopting it.
No DEVAI release or new HTTP task is necessary for the existing RC interface.

Keep all fifteen existing `rc` nodes, exact argv, environment/toolchain/input
binding and dependencies: engines, API contracts, lint families, typecheck,
unit tests, integration tests, build, reference apps, database/RLS, e2e, docs,
`test:performance`, security, Doctor and release preparation. The existing
`test:performance` executes five cold-unit subprocess samples, not k6. Preserve
its actual defaults, comparisons and thresholds; it cannot stand for HTTP latency.
Keep ordinary coverage thresholds and every product/security/tenancy assertion.
Formatting, lint, type integrity, generated consistency, emitted API compatibility,
migrations/upgrade/import, package boundaries, zero-high security policy and
supported product correctness remain mandatory. No gate may be replaced by a
fabricated receipt, cached foreign-candidate result or skipped test.

Keep exact-candidate signed RC and independently verified public evidence,
protected PR/strict branch integration, required checks, exact action/commit
Owner receipts, exact-main registry preflight, normal Changesets 1.6.0 version
staging, `publish:true`, protected environment approval and existing immutable
publication controls. Independently verify all 44 actual artifacts/integrities,
tag and release, retaining the RC tag. Failed, partial or ambiguous publication
still stops recovery mutation pending new exact authorization.

## Exact publication-check mechanism

`verify-missing-evidence.mjs` currently demands a unique successful exact-head
`k6` check at actual publication. For **only** this validated 1.6.0 machine scope,
the Engineer changes that demand to unique completed successful exact-head
`verified-local-rc`, with the existing verifier independently enforcing exact-tree
signed RC. Require clean exact HEAD, uniform root/all-roster 1.6.0, roster digest,
closed policy validity and exact fifteen-node transitive RC closure. Missing,
malformed, unknown or mismatched inputs refuse; they never activate a fallback
exception. All other release versions retain the original k6 publication demand.
Protected static/security checks and the ordinary signed release gate remain.
Inspector independently verifies positive exact scope and negative versions,
rosters, graph, policy, candidate and duplicate/failed/stale-check witnesses.

No `.github/workflows` change is required for this scope. Current hardening runs
only by explicit dispatch or its weekly schedule, with no push/PR trigger; do not
dispatch it tonight. Preserve workflow controls and their receipt requirements.
`.devai/config` remains generated through installed registered binding only.

## Truthful omissions and follow-up

Record HTTP/k6 performance as **NOT_OBSERVED**, mutation as **NOT_RUN**, and actual
audit cells/verdict without substituting PASS or broadening the two existing N/A
cells. `readiness_promoting=false` remains mandatory. Disclose the exact bounded
scope and publication-time scorecard/available observation in release evidence
and notes. This publication supplies no endpoint SLO, original workload/native
floor, complete performance, fully green audit or production provider approval.
INV-PERF-001 retains its SLOs and future qualification obligation; this one-version
publication scope does not change tests, thresholds, sample sizes or old outcomes.

DETRAN adoption, real signing-provider samples/approved trust-policy inputs,
consumer migration proofs and issue closure remain evidence-dependent follow-up.
Their absence alone does not block package publication when supported production
readiness guards correctly refuse unapproved LTA/provider use. Preserve those
guards and all existing non-LTA behavior. Do not claim provider acceptance, close
an issue with missing required proof, or install the new pin in DETRAN before
independent final package publication verification.
