# ADR-OUTBOX-0002 — Event log and delivery

**Decision source:** DETRAN C-0002 A1 §8.1 UPS-OBX-01…02, included in STYNX 1.5.0 by OD-S15-03. **Companion:** [CTG9 OBX contract](../../work/rounds/R-0002/ctg9-obx-contract.md).

**Amendment:** [ADR-OUTBOX-0003](ADR-OUTBOX-0003-configurable-role-and-consumer-storage.md) makes the application SQL role name configurable, adds consumer-owned outbox storage as a supported mode and adds named destinations. The historical text below remains for provenance.

## Context and supersession

ADR-OUTBOX-0001 promoted PEC's one-row-per-aggregate upsert. Its statement that one outstanding message per aggregate satisfies ordering, and that append-only replay requires a later decision, is superseded **only for the new append mode**. Existing `enqueue`, aggregate ACK, HMAC, claim-only dispatch and legacy storage semantics stay valid. A1 requires distinct facts, tenant-key dedup, SSE replay and a durable attempt/ACK ledger. The existing upsert table cannot be an SSE event source.

## Decision

Add an immutable tenant-scoped event log, a mutable per-event delivery projection and an append-only attempt/ACK ledger. `appendInTransaction(trx,event)` is the public OFS port; `appendManyInTransaction(trx,events)` records multiple facts in one transaction. Both use the caller's actual `Transaction`, derive tenant from the SQL session and require READ COMMITTED. Dedup is `(tenant_id,idempotency_key)`, not aggregate; conflicting content under a reused key fails. New public `OutboxService.dispatchEventsDue(limit)` and `OutboxService.ackEvent(input)` operate only on event-mode rows. Delivery claims only the oldest nonterminal event for each aggregate, with lease and two-scheduler `SKIP LOCKED` claiming. ACK identifies an event or idempotency key plus tenant and cannot guess an aggregate among multiple events. Composite tenant/event FKs protect the owner-role ledger association. Dispatch remains at least once after lease reclamation; provider dedup uses event ID/key. Invalid HMAC or unknown/mismatched event identity has no trusted tenant/event FK and is recorded through `OutboxService.recordUnboundAck(rawBody, reason)` in an independent owner transaction in an unbound ACK quarantine with raw bytes/hash and reason; rejection cannot roll that diagnosis back. The legacy acknowledgement table and `UNIQUE(message_id)` remain intact.

For SSE, serialize appends per tenant on a tenant-clock row held until commit. Both `appendInTransaction` and `appendManyInTransaction` first acquire `outbox.legacy_ownership FOR SHARE` on their own Transaction: the common acquisition order is marker SHARE → audit advisory → clock; a prior domain audit is handled by NOWAIT as specified below. Assign millisecond `created_at` and UUIDv7 using a full global `bigint` sequence in its ordered bits while holding that lock. The public cursor is `(createdAt,id)`; `now`, `findById`, `listSince` use the primary, FORCE RLS and actual SQL tenant identity. `now` locks only the clock row, applies local `lock_timeout`, and limits per-tenant/process connection occupancy; the existing backend maps source failure to 503. A legacy UUIDv4 maps persistently to the migrated UUIDv7. No purge or additional public limit is decided for 1.5.0.

The precise invariant is that any transaction **holding the tenant clock also holds marker SHARE acquired before the clock**. The common append path acquires marker→advisory→clock. A handler that already wrote an audited domain row may hold advisory before append; in that case append acquires marker with `FOR SHARE NOWAIT`, and 55P03 requires rollback/retry of the whole caller transaction. Every legacy marker acquisition (`enqueue`, claim, ACK, retry and dispatch-failure persistence) likewise uses NOWAIT. In the A/B/C queue, B holds marker SHARE and waits for A’s advisory, C has marker UPDATE queued, and A requests compatible SHARE: PostgreSQL may grant A immediately despite C waiting. The required result is bounded completion of A/B before C, no 40P01 and no duplicate effect; 55P03 is permitted but not required. A separate deterministic NOWAIT sensor has C already holding UPDATE before A requests SHARE; A receives 55P03, rolls back the full caller transaction, and retries with the same key. Legacy callers need no pre-acquisition rule; opt-in a cutover that already holds UPDATE can surface retryable `OutboxOwnershipContentionError`, and a full retry after committed cutover may instead produce `OutboxLegacyCutoverError`. `now()` is a short independent app-role transaction; it rejects an ambient held write transaction as `OutboxClockAmbientTransactionError` before acquiring a connection, so it never waits on clock while holding application locks.

The shared audit chain must be made linear **before** append's clock lock. Migration ≥0021 redefines `audit.fn_row_change`, `audit.write` and `audit.write_command_event` to take one advisory key per tenant, using a fixed NULL sentinel, before selecting the head. Under READ COMMITTED, each computes `occurred_at = greatest(clock_timestamp(), head.occurred_at + 1µs)`, calls `audit.ensure_monthly_partition` with **that chosen timestamp**, then hashes and inserts that same timestamp; a second `clock_timestamp()` at the month boundary would select the wrong partition. RR/SERIALIZABLE fail before head selection with SQLSTATE `40001`, fixed MESSAGE `audit_chain_requires_read_committed`, and HINT to use RC; data maps this specific error to nonretryable `AuditChainIsolationError`. `audit.write` remains revoked to app. Owner `AuditSqlSink` may pass a real tenant. A transaction-local `stynx.audit_chain_key` binds the first chain key; a change raises `STY41` before another advisory, mapped to `AuditChainKeyMismatchError`. This GUC is transaction self-protection, not a boundary against arbitrary SQL. Head indexes cover `(tenancy_id,occurred_at DESC,event_id DESC)` plus NULL partial case; lookups split equality and IS NULL. The Engineer changeset and migration guide disclose that `TxOptions.isolation` becomes effective and audited RR/SERIALIZABLE writes now fail typed.

Legacy audit hashes and timestamps are untouched. Migration follows `previous_hash` links and records linear, temporally misordered, forked and hash-mismatched segments, including NULL tenant, without aborting solely for a legacy defect. It records tips/diagnostics, then seals each segment with an explicit new-epoch anchor after its greatest timestamp under the advisory. `audit.verify_chain` keeps public columns and partitions `lag()` by epoch; legacy invalid rows remain invalid. `audit.verify_current_epoch(tenant,limit)` starts at the anchor regardless of how many legacy rows precede it. A diagnostic function exposes legacy state. Actual migration errors abort. A hash mismatch in release data requires Owner evaluation before final publication.

`Database.txIndependent` is additive: it refuses a held connection before pool acquisition, including across derived request/system contexts, using a mutable AsyncLocalStorage holder with `held` and `strict` cleared in `finally`. In strict item scope any `Database.tx` that would open a second connection fails typed; legacy `Database.tx` outside strict mode retains its behavior. `TxOptions.isolation` applies at top-level before the first query; nested mismatch fails. The item validates isolation and read/write state on the live connection. Audit chain lock precedes clock. An OFS item seals its last append with `SET LOCAL transaction_read_only = on`; a later write maps SQLSTATE 25006 to `ReadOnlyViolationError`. Generic append within a CTG5 transactional command may leave the connection writable for the command envelope's later audit/idempotency writes; it retains the clock until commit, and the advisory→clock order remains mandatory. This is a narrowly required composition, documented in the contract and bounded at SSE `now()` by timeout/admission. It does not change CTG5's published path.

Migration ≥0021 creates storage and a `migrated_event_id` link but **does not copy or activate** legacy rows. Legacy-only adopters continue `enqueue`/`dispatchDue`/`ack` unchanged. Native append events are claimable by `dispatchEventsDue` in both LEGACY and NEW; the marker NEW gate applies only to migrated provenance. `OutboxService.cutoverLegacyMessages()` is an explicit, idempotent opt-in for the default tables only; custom `table`/`ackTable` options fail typed before mutation and remain legacy. A singleton `outbox.legacy_ownership` marker is read `FOR SHARE` before row locks by every legacy enqueue/claim/ACK/retry/dispatch-failure path and locked `FOR UPDATE` by cutover. Cutover locks all legacy rows `FOR UPDATE` without `SKIP LOCKED`, copies each once, writes `migrated_event_id`, then commits marker NEW atomically. It may acquire the clock **after** the marker but cannot call an audit writer or touch an audit-triggered table while holding marker UPDATE; an optional audit record is written in a separate owner transaction after commit. Legacy claim excludes marked rows; enqueue after NEW fails typed rather than silently appending. Legacy ACK of a marked row updates its old record plus the new ACK ledger/projection in one transaction, preserving the published HMAC gate and aggregate ambiguity rule. A legacy send failure returning after cutover uses marker SHARE and mirrors the failed attempt and policy retry time into the projection, moving `SENT_UNRESOLVED → ERROR` only if no terminal ACK has since committed. Existing SENT in flight otherwise remains `SENT_UNRESOLVED` without automatic reclaim until valid ACK or owner reconciliation; terminal ACKED is never redelivered. An append holding clock already holds marker SHARE, preventing cutover's UPDATE; cutover holding UPDATE prevents append from reaching clock. A legacy audited-domain-write→enqueue may take advisory before marker; a queued cutover UPDATE alone does not prove its NOWAIT SHARE will fail. The three-party sensor accepts immediate SHARE grant and requires cutover to commit after A/B; a separate held-UPDATE variant proves typed 55P03 and full retry. `55P03`/`40P01` rolls back the whole operation and retries idempotently from its boundary, not in the aborted transaction. A rollback before commit rolls back both copies and marker, leaving legacy authority; after commit there is no automatic reversal. History without exact bytes is marked unavailable, never fabricated. Inspector proves legacy-only delivery, native append delivery without cutover, append+enqueue and audited-write+enqueue races, late legacy failure, ACK racing cutover, idempotent reexecution, and legacy/new schedulers without double claim. Engineer updates canonical DDL, seeds and DB tests; no historical migration is edited.

After marker UPDATE but before the first cutover mutation, lock the target tables in fixed order with `LOCK TABLE ... IN SHARE ROW EXCLUSIVE MODE` to exclude concurrent trigger DDL, then inspect `pg_trigger`/`pg_proc` for enabled `audit.fn_row_change` triggers on every table the cutover will mutate, including physical partitions of messages, events, projections, map, ledgers, clock and ownership marker. Abort with `OutboxCutoverAuditedTableError` if any is found. The ≥0021 DDL does not attach those triggers. `recordDispatchFailure` owns an idempotent transaction keyed to the legacy message and attempt ordinal; 55P03/40P01 causes bounded backoff and a full retry of persistence only, never another send. Exhaustion yields a per-row error outcome and the dispatch loop continues other claimed rows. Inspector injects an audited trigger, tests a long cutover marker lock after send failure, and checks the A/B/C lock queue in PostgreSQL.

## Consequences

SSE replay has commit-monotonic visibility, at-least-once delivery and no replica-staleness gap. A long generic transaction after append retains the tenant clock and can cause same-tenant SSE `now()` to return 503; clients retry. The NULL audit chain sentinel and per-tenant clock can serialize writers, so contention and pool occupancy need measurements. No release conformity is claimed until migration, RLS, scheduler and Inspector sensors pass.
