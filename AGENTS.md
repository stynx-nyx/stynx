# STYNX agent guide

This repository uses the same engineering contract for human and automated
contributors. Read [docs/meta/development-contract.md](docs/meta/development-contract.md)
before making changes.

Work only within the requested scope, preserve unrelated user changes, and
verify changes in proportion to their risk. Never weaken or delete tests to
make a change pass. Use Conventional Commit subjects.

For repository-specific boundaries, tenancy and RLS requirements, database
change obligations, generated tooling, and release-state references, the
development contract is authoritative.
